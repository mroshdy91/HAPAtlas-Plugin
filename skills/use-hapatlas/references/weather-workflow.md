# Phase 1 Weather workflow

1. Call `hapatlas_project_scout(action: "weather")` for the exact selected session and retain the revision. For the complete engineer-visible form, send `filter: {"tab":"design-parameters","detail":"engineering","units":"IP|SI"}`. The default scout stays compact.
2. Search `scope: libraries`, `category: design-weather`. Prefer exact library, non-zero WMO, native station, or catalog-city identity. Coordinates may rank by distance, but the agent must inspect ambiguous choices. A HAP 5.1 native WMO zero is a sentinel, not a selector.
3. Inspect the exact `library_ref`. Review source, station name, coordinates, elevation, cooling/heating conditions, timezone/DST, and native adapter differences.
   - Public longitude is conventional east-positive/west-negative for both adapters. HAP 5.1's west-positive native value is also returned explicitly for UI/readback diagnosis; never copy that native sign into a semantic coordinate input.
4. On HAP 6.3, separately search and inspect `simulation-weather`. On HAP 5.1, stop on the guarded simulation workflow; never use design weather as simulation weather.
5. Select the matching Weather action: `design.select-station`, `design.edit-parameters`, `design.select-and-override`, or `simulation.select-station`. Dry-run that action with top-level `weather.units`, then apply the unchanged action/payload only against the unchanged revision. Omitted parameter fields preserve their native values.
   - Both adapters: latitude, longitude, elevation, time-zone offset, summer dry-bulb/wet-bulb/daily range, winter dry-bulb/wet-bulb, ground reflectance, soil conductivity, cooling-month range, and daylight-saving selection/dates.
   - HAP 6.3 only: climate-zone selection, installed cooling/heating condition selection, and outdoor-air CO2. Selecting `user_defined` or entering direct summer/winter values changes the native condition category to User Defined.
   - HAP 5.1 only: atmospheric clearness. Region/location/city is selected through the exact design-weather library identity, not free text.
   - Data Source is native read-only provenance. A direct override is stored by HAP as user-modified/user-defined; the agent cannot forge a Carrier source label.
6. Scout Weather again. A design-weather change makes affected design sizing stale and requires native recalculation. A simulation-only change does not invalidate design sizing.
7. The dedicated Weather input report is visible in HAP but its non-UI renderer is not yet promoted. The engineer exports that native report from HAP and reviews every page before saving. Do not substitute a Building or Space Model report. A raw `weather-input` report request returns guided `REPORT_TEMPLATE_UNAVAILABLE`. A CSV-created message confirms only the selected CSV output; verify all 8,760 hourly rows separately. If TER32 reports `Error creating font`, reject the PDF even when it opens: report text can be absent while charts still draw. Regenerate the affected report portion separately after a clean HAP start and retain the warning for support.

Use `scope: documentation` to search exact-build installed HAP help when a visible Weather field or report is unfamiliar. Help results are knowledge refs, not project libraries or proof that a mutation is promoted.

Currently guarded or separately gated: HAP 6.3 atmospheric clearness, HAP 5.1 climate-zone/CO2/condition-percentile selectors, edited monthly/hourly Design Temperatures tables, Design Solar table mutation, HAP 5.1 simulation import/selection, and Save as Default Weather. The promoted Design Parameters and legacy catalog-city/native-WMO-zero portfolios are Available after exact selection/readback, UI, calculation, report, Save, and close/reopen acceptance as applicable.

For HAP 5.1, `catalog_city_id` is the legacy native catalog identity and `wmo_station_id` is a separate geographic identity. When Carrier stores a native WMO zero sentinel, HAPAtlas returns semantic `wmo_station_id: null` plus `native_wmo_station_id: 0`; select by exact `library_ref` or `catalog_city_id`, never WMO `"0"`. After any live apply, trust `pending_user_save` only from a fresh scout: HAPAtlas combines the verified live native dirty owner with its current revision-locked unsaved transaction because Carrier's dirty flags may remain false after a retained Weather edit.
